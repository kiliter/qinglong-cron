# Lucky 配置备份到 WebDAV 定时任务设计

## 1. 目标

为青龙面板订阅仓库初始化首个定时任务。任务每天凌晨 03:00 依次备份多个 Lucky 实例的配置，将备份文件上传到同一个 WebDAV 服务，仅保留最近 30 天，并在每次任务结束后通过 Server酱发送中文汇总通知。

仓库名称为 `qinglong-cron`，设为 GitHub 公开仓库。本地项目目录最终由 `/opt/cron` 更名为 `/opt/qinglong-cron`。代码仓库不得包含 OpenToken、WebDAV 密码或 Server酱 SendKey 等真实凭据。

## 2. 实现方案

采用 Python 3 标准库实现单文件青龙任务，不引入第三方依赖。相较 Shell 方案，Python 对 JSON 配置、WebDAV XML、日期和异常处理更稳定；相较 Node.js 方案，Python 标准库无需额外安装依赖，更适合青龙订阅后直接运行。

任务文件使用青龙可识别的定时注释，默认五段 Cron 表达式为 `0 3 * * *`。代码中的方法、关键判断和配置字段均添加中文注释或说明。

## 3. 配置模型

青龙通过环境变量 `LUCKY_BACKUP_CONFIG` 提供 JSON 配置，配置包含以下内容：

- `luckies`：Lucky 实例数组。每项包含实例名称、面板基础地址和 OpenToken；可选配置备份 API 路径及是否校验 TLS 证书。
- `webdav`：唯一 WebDAV 目标，包含服务地址、用户名、密码、远端根目录及是否校验 TLS 证书。
- `serverchan`：包含 Server酱 SendKey；任务每次执行均发送一条通知。
- `retention_days`：备份保留天数，默认值为 30。

公开仓库只提供使用虚假凭据的配置示例。程序日志和通知不得输出 OpenToken、WebDAV 密码或完整 SendKey。

## 4. 组件边界

### 4.1 配置加载与校验

负责读取环境变量、解析 JSON、校验必填字段和生成不可变的运行配置。配置不完整时，在进行任何下载、上传或删除操作前终止任务；若已能安全读取 Server酱配置，则尝试发送配置错误通知。

### 4.2 Lucky 备份客户端

负责通过每个实例的 OpenToken 调用 Lucky 2.x 配置备份接口。默认使用当前接口路径，并允许实例级覆盖路径，以适应不同 Lucky 版本。下载结果必须满足以下条件才可进入上传阶段：

- HTTP 请求成功；
- 内容不为空；
- 文件具有 ZIP 签名，避免将登录页或 JSON 错误信息误当成备份；
- 文件名在本地重新生成，不信任服务端返回的路径信息。

### 4.3 WebDAV 客户端

负责递归创建任务目录、上传备份、列出远端文件及删除过期备份。远端目录结构为：

```text
/qinglong/lucky-backup/<实例名称>/<实例名称>_YYYYMMDD_HHMMSS.zip
```

实例名称在用于路径前必须安全化，防止路径穿越或产生非法路径。清理操作仅扫描任务根目录下的实例子目录，只删除同时满足以下条件的文件：

- 文件名符合本任务固定命名规则；
- 扩展名为 `.zip`；
- WebDAV 修改时间早于当前时间减 30 天。

若远端文件没有可解析的修改时间，则保留该文件。只有本轮至少有一个备份成功上传后才执行清理，避免在上游全部失败时只执行删除操作。

### 4.4 Server酱通知

负责将本轮任务结果汇总为一条中文消息。消息包含各 Lucky 实例的下载和上传结果、过期文件清理数量、失败阶段及总耗时。通知正文不包含任何真实凭据。通知发送失败会记录在任务结果中，并使进程返回非零状态。

### 4.5 任务编排

任务先完整校验配置，再按配置顺序逐个处理 Lucky 实例。单个实例失败后继续处理后续实例，确保一个故障实例不会阻止其他实例完成备份。所有实例处理结束后执行受限范围的过期清理，最后发送一次 Server酱汇总通知。

## 5. 异常处理与退出状态

所有网络请求设置连接和读取超时，并检查 HTTP 状态码。临时备份写入系统临时目录，任务结束后自动清理。

以下任一情况发生时，任务最终返回非零退出码，以便青龙面板标记失败：

- 任一 Lucky 实例下载或校验失败；
- 任一 WebDAV 上传失败；
- WebDAV 目录创建或过期清理失败；
- Server酱通知发送失败；
- 配置加载或校验失败。

即使出现部分失败，任务仍尽量完成剩余实例处理并发送通知。成功上传的新备份不会因清理失败而删除。

## 6. 测试与验收

自动化测试使用 Python 本地模拟服务，不连接真实 Lucky、WebDAV 或 Server酱。测试至少覆盖：

- 多个 Lucky 实例均成功备份并上传；
- 单个 Lucky 失败时其他实例继续运行；
- Lucky 返回非 ZIP 内容时拒绝上传；
- WebDAV 只删除 30 天前且符合命名规则的备份；
- 无法解析时间或不符合命名规则的文件不被删除；
- Server酱在成功和失败场景下均收到一次汇总；
- 日志与通知不泄露配置中的真实凭据；
- 任一关键阶段失败时进程退出码非零。

验收时还需执行 Python 语法检查和全量测试，并检查 Git 状态，确认公开提交中不存在真实密钥。

## 7. 仓库交付

仓库包含中文 `README.md`、青龙订阅及环境变量配置说明、脱敏示例、任务代码和自动化测试。完成本地验证后，将目录更名为 `/opt/qinglong-cron`，创建公开 GitHub 仓库 `kiliter/qinglong-cron` 并推送默认分支。

青龙订阅白名单必须精确填写 `tasks/lucky_webdav_backup.py`。任务目录和测试目录不放置 `__init__.py`，避免青龙把包初始化文件识别为候选定时任务。自动化测试通过项目根目录加载 Python 命名空间包，不依赖初始化文件。
